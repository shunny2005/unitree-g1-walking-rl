# G1 model provenance (this project)

Upstream files (`g1.xml`, `g1_mjx.xml`, `g1_with_hands.xml`, `scene*.xml`,
`assets/` meshes, `LICENSE`, `CHANGELOG.md`, upstream `README.md`) are
vendored, unmodified, from
[mujoco_menagerie](https://github.com/google-deepmind/mujoco_menagerie)
`unitree_g1/`, commit `da76818e269b82289eba39808e2fb91d679d6994` (fetched
2026-08-26). Copied into this project on 2026-09-18 from the sibling
`../standing-rl` project's own vendored copy (same commit, same files) to
avoid re-fetching an already-verified asset; see
`docs/DECISIONS.md` ADR-001 for why.

The model is `g1_29dof_rev_1_0`: 29 actuated joints (12 leg, 3 waist, 14
arm/wrist) plus a 6-DOF floating base.

## `g1_walk.xml` / `scene_walk.xml` — this project's derived model

Generated by `scripts/build_walk_model.py` from upstream `g1.xml`. The
only change: the 12 leg joint actuators go from MuJoCo `<position>`
(upstream default `kp=500 dampratio=1`, uniform gain) to `<motor>`
(direct torque), so our own environment can apply distinct PD gains per
leg-joint group (see `control/pd_controller.py`) instead of MuJoCo's
built-in uniform position controller. `ctrlrange`/`forcerange` on each
new motor actuator equals that joint's own `actuatorfrcrange` from
`g1.xml` -- no torque limit changed, only the control mode. Waist and arm
actuators are untouched; this project does not RL-control them (see
`docs/DECISIONS.md`).

`scene_walk.xml` also pins floor friction explicitly (`1.0 0.005
0.0001`, MuJoCo's own default values, made explicit rather than implicit)
so it is a known, versioned quantity.

The same transform was independently applied and validated for the
identical robot in the sibling `../standing-rl` project
(`assets/g1/README.md` there); we re-derived it ourselves via
`scripts/build_walk_model.py` rather than copying the derived XML, so the
transform is understood and owned in this project rather than trusted
blindly. Regenerate by re-running the script whenever upstream `g1.xml`
changes.
